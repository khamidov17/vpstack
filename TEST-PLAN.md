## CRITICAL CI Gates (block release if any fail)

### CG1 — B1 baseline reproducibility
- **What:** `bin/vpstack-b1` produces EER within ±0.5% of published number on dev set.
- **Where:** `tests/test_binaries.py`
- **Why:** Wrong baseline = wrong citations = community trust gone. The number is the product.
- **How:** Pin random seed, run baseline on dev fixture, assert `abs(eer - PUBLISHED_B1_EER) < 0.005`.
- **Frequency:** Every PR.

### CG2 — B2 baseline reproducibility
- Same as CG1 but for B2. `tests/test_binaries.py`.

### CG3 — Telemetry sanitization (off mode)
- **What:** When `telemetry=off`, `vpstack-telemetry-log` makes ZERO network calls.
- **Where:** `tests/telemetry/test_off_mode_zero_network.py`
- **Why:** Privacy promise. Off must mean off.
- **How:** Mock socket layer; assert no DNS lookups, no TCP connects.

### CG4 — Telemetry sanitization (forbidden keys)
- **What:** No payload (any mode) ever contains: file paths, code, hypothesis text, eval numbers, repo names, branch names, hyperparameters, user prompts, error message bodies (only error class names).
- **Where:** `tests/telemetry/test_payload_sanitization.py`
- **Why:** P5 promise to researchers.
- **How:** Property-based test — run skills with synthetic privacy-marker strings, capture all telemetry payloads, assert none contain marker.

### CG5 — Auto-activation silence on non-voice repos
- **What:** Skills exit silently (zero stdout, zero AskUserQuestion) on 3 known non-voice fixture repos.
- **Where:** `tests/activation/test_non_voice_silent.py`
- **Why:** Success criterion #3. The single biggest UX promise.
- **How:** Spawn skill in 3 fixture repos (`fixtures/non-voice/{rails-app,go-cli,python-ml}/`), assert exit code 0 and empty stdout.

### CG6 — Auto-activation activates on voice repos
- **What:** Skills detect and proceed on 3 known voice fixture repos.
- **Where:** `tests/activation/test_voice_detected.py`
- **Why:** Success criterion #3.
- **How:** 3 fixture repos (`fixtures/voice/{vp2026-mock,speechbrain-anon,custom-voice-priv}/`), each with a different detection signal triggering DETECTED_*.

### CG7 — vp_log_experiment atomic write
- **What:** No half-written state in `~/.vpstack/projects/{slug}/experiments/{id}/` after kill -9.
- **Where:** `tests/mcp/test_log_experiment_atomic.py`
- **Why:** Researcher kills a job → resumes → finds either a complete log or no log, never partial.
- **How:** Write to tmpfile, fsync, atomic rename. Test with simulated mid-write SIGKILL.

## Key Interactions to Verify

1. **Install flow** — `npx vpstack@latest` on macOS / Linux / WSL. Detects Claude Code or Codex or Cursor. Telemetry prompt presents 3 options. Files land in correct locations.
2. **First skill use on voice repo** — heuristic detection fires, first-run prompt asks once, user choice persisted in `<repo>/.vpstack/`.
3. **First skill use on non-voice repo** — zero output. Skill exits 0.
4. **Full experiment cycle** — `/vp-hypothesis` → `/vp-spike` → `/vp-baseline-compare` → `/vp-eval` → `/vp-writeup`. Each step writes to `~/.vpstack/projects/{slug}/`. Final writeup references all prior artifacts.
5. **Auto-update prompt** — bump published version. Next skill invocation prints `UPGRADE_AVAILABLE`. User picks "skip this version" → no re-prompt for that version.
6. **MCP tool from external client** — Claude Desktop with vpstack-mcp configured calls `vp_run_baseline("B1", ...)`. Returns structured result.

## Edge Cases

1. Both `<repo>/.vpstack/enabled` and `.disabled` exist — `disabled` wins, warning logged.
2. Symlink loop in parent-dir traversal during `vpstack-detect` — bounded walk exits cleanly.
3. Network down during version check — silent skip, no error to user.
4. GPU OOM mid-baseline — `vp_run_baseline` returns `{"ok": false, "error": {"code": "GPU_OOM", ...}}`.
5. VP2026 data not downloaded — `vp_run_baseline` returns `{"ok": false, "error": {"code": "DATA_MISSING", "hint": "Download from ..."}}`.
6. Disk full during `vp_log_experiment` — structured error, no partial file.
7. User runs skill in non-interactive shell (CI / pipe / no TTY) — first-run prompt would block; needs `--headless` flag that auto-picks `disabled`.
8. User has 1000+ experiments in `~/.vpstack/projects/{slug}/experiments/` — `vp_search_experiments` performs acceptably (<1s for jsonl scan).
9. User runs `/vp-eval` against held-out "test" split without `--official` flag — blocked with explanation. Prevents accidental test-set overfitting.
10. Concurrent skill invocations from two terminals on same project — both can run, no lock file conflicts.
11. `~/.vpstack/config.json` corrupt or missing fields — repair with defaults, don't crash.
12. Telemetry endpoint returns 500 — silently retry once, then drop. Never block skill.
